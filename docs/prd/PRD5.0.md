## 0. 文档说明

PRD 5.0 将 Skill Panel 从单纯的 Skill 文件管理工具，重新定义为“以 Skill 为第一阶段入口的 AI 工作资产管理平台”。本版本完整吸收 96 项产品边界决策，统一产品定位、功能范围、权限安全、扫描机制、数据统计、安装更新、生命周期和底层数据模型。

PRD 5.0 描述的是 Skill Panel 1.x 的完整目标形态，并按优先级拆分交付顺序。产品界面在 1.x 阶段只围绕 Skill 展开，底层统一采用 Asset 架构，为后续 Prompt、Workflow、MCP Server、Agent、Rules、Template、Script 和 Knowledge 等类型预留扩展能力。

## 1. 产品概述

### 1.1 产品名称

Skill Panel

### 1.2 当前产品定位

Skill Panel 1.x 是一款本地优先的 Skill Manager，用于发现、浏览、搜索、分类、分析、编辑、安装、更新和管理电脑中的 Skill。

产品不承担 Skill 的直接执行，不替代 Claude Code、Codex、Gemini CLI、Cursor、Warp 等宿主，也不定位为 IDE。用户在 Skill Panel 中完成资产认知与管理，需要执行时先复制调用方式，也可从详情页跳转至对应宿主。

### 1.3 核心价值

产品首先解决以下问题：

1. 电脑里到底有哪些 Skill，分别存放在哪里。
2. 每个 Skill 包含哪些文件、内容和调用方式。
3. 哪些 Skill 正在使用，调用次数和 Token 情况如何。
4. 哪些 Skill 重复、失效、丢失、存在本地修改或可更新。
5. 如何在不破坏本地文件的前提下编辑、更新、合并、归档或卸载。
6. 如何把分散在多个宿主和目录中的同一 Skill 统一管理。

### 1.4 核心价值排序

| 优先级 | 用户价值 | 产品对应能力 |
|---|---|---|
| 1 | 找到并看清 Skill | 全盘扫描、Library、搜索、详情、文件树 |
| 2 | 整理和管理 Skill | 分类、标签、重复组、多实例、Missing、Archive |
| 3 | 修改 Skill | 编辑器、草稿、Diff、文件快照、完整包快照 |
| 4 | 了解 Skill | 调用次数、会话数、Token、活跃度、数据可信度 |
| 5 | 安装和更新 Skill | GitHub、Git、ZIP 安装、更新、来源绑定、卸载 |

### 1.5 长期战略定位

| 产品阶段 | 定位 | 核心范围 |
|---|---|---|
| Skill Panel 1.x | Skill Manager | 发现、管理、分析、编辑、安装 Skill |
| Skill Panel 2.x | AI Asset Manager | 扩展 Prompt、Workflow、MCP、Agent、Rules、Template、Script 等资产 |
| Skill Panel 3.x | AI Workspace | 连接资产、自动化、工作流、执行和分析，形成完整 AI 工作闭环 |

长期方向为 AI Assets 的统一管理入口。安装生态按以下顺序演进：1.x 以本地资产中心为主；2.x 增强包管理能力；3.x 再评估官方仓库、第三方仓库、企业私有仓库和开放生态平台。

## 2. 产品目标与非目标

### 2.1 产品目标

1. 用户首次启动后，可在明确授权的前提下扫描整台电脑并发现 Skill。
2. 用户可在同一 Library 中查看所有 Skill，并使用表格、卡片和目录树三种视图。
3. 用户可查看完整 Skill 包目录、文本内容、规模、Token、来源、实例和使用数据。
4. 用户可通过分类、标签、搜索、筛选、排序、收藏和重复组整理大量 Skill。
5. 用户可在默认只读模式下安全浏览，并按 Skill 或目录授予写入权限。
6. 用户可编辑 SKILL.md 和其他文本文件，并通过草稿、Diff、快照和冲突检查降低误操作风险。
7. 用户可查看使用次数、会话数、Token 和活跃度，同时清楚了解数据来源和可信度。
8. 用户可通过 GitHub、Git 和 ZIP 链接安装、更新、绑定来源和卸载 Skill。
9. 用户可处理重复、多实例、本地修改、Missing、Archive、部分更新和更新冲突。
10. 产品底层以永久 UUID 和 Asset 模型维护历史连续性。

### 2.2 非目标

1. 1.x 不在 Skill Panel 内直接运行 Skill。
2. 1.x 不提供完整 IDE、调试器或宿主替代能力。
3. 当前版本不使用 AI 自动改写 Skill，不对语义内容作自动删除或重构决定。
4. 当前版本不承担跨设备迁移和完整数据恢复。
5. 当前版本不建立官方 Skill 商店或统一官方生态。
6. 当前版本不保证能从所有宿主获得逐 Skill 使用数据。
7. 当前版本不默认保存完整提示词和回答正文。
8. 当前版本不自动执行安装脚本、依赖安装或初始化命令。
9. 当前版本不把普通搜索、筛选、查看详情和复制路径记录进 Activity。
10. 当前版本不基于名称直接认定两个 Skill 重复或属于同一实体。

### 2.3 产品原则

| 原则 | 说明 |
|---|---|
| 本地优先 | Skill 文件、索引、分类、快照和统计默认保存在本机 |
| 默认只读 | 扫描与浏览不等于获得写入权限，写操作需单独授权 |
| 数据可信 | “暂无数据”“0 次”“部分匹配”必须严格区分 |
| 用户确认 | 扫描变化、冲突覆盖、脚本执行、额外目录访问和高风险删除均由用户确认 |
| 可回滚 | 重要写操作前创建快照，失败后提供明确回滚路径 |
| 单一实体 | 名称、路径、版本和来源可变，永久 UUID 才是实体主键 |
| 规则驱动 | 当前阶段使用固定规则分类、检查和优化，不引入 AI 自动决策 |
| 渐进扩展 | UI 聚焦 Skill，底层按 Asset 架构建设 |

## 3. 目标用户与使用场景

### 3.1 目标用户

主要面向在本地使用 Claude Code、Codex、Gemini CLI、Cursor、Warp 或其他 AI 开发工具，并维护多个 Skill 的个人开发者、AI 工具重度用户和小型团队成员。

### 3.2 典型用户特征

- Skill 分散在多个宿主目录、自定义目录、Git 仓库和下载目录中。
- 不清楚电脑中实际存在多少 Skill。
- 经常忘记某个 Skill 的用途、调用方式和存放位置。
- 存在重复安装、多个宿主副本和本地修改分叉。
- 希望了解 Skill 使用频率和 Token 成本，但宿主数据并不完整。
- 需要编辑和更新 Skill，又担心误覆盖或无法恢复。
- 希望通过链接安装 Skill，但不愿依赖终端命令完成全部流程。

### 3.3 核心使用场景

| 场景 | 用户目标 | 完成标志 |
|---|---|---|
| 首次发现 | 找出电脑中全部 Skill | 完成全盘扫描并确认正式索引 |
| 日常查找 | 快速定位某个 Skill | 通过搜索、分类或目录树选中 Skill |
| 查看内容 | 看清 Skill 的用途和文件 | 打开快速详情或完整 Detail |
| 复制调用 | 获取调用命令或提示词 | 一键复制并得到成功反馈 |
| 使用分析 | 判断哪些 Skill 正在使用 | 查看调用、会话、Token、活跃度和可信度 |
| 内容编辑 | 安全修改 SKILL.md 或其他文本 | 授权、编辑、查看 Diff、保存并生成快照 |
| 重复整理 | 处理相同或相似 Skill | 比较实例并选择保留、归档、关联或合并 |
| 安装更新 | 从链接安装或更新 Skill | 完成检查、确认、写入、验证与记录 |
| 丢失恢复 | 处理被移动、删除或离线的 Skill | Relink、恢复、归档或删除 |

## 4. 版本范围与交付优先级

PRD 5.0 定义完整 Skill Panel 1.x。实际研发按以下顺序交付，后续阶段不得破坏前一阶段的数据模型与交互逻辑。

### 4.1 P0：核心可用版本

1. 首次启动授权和全盘扫描。
2. 扫描进度、暂停、取消、失败目录记录和实时发现结果。
3. 正式索引、扫描结果、待确认变更集三层模型。
4. Library 表格、卡片、目录树三种视图。
5. 搜索、筛选、排序、分类、标签、收藏和快速详情。
6. Skill Detail、目录树、文本预览、包规模与 Token 统计。
7. 重复检测、重复组、多实例分组和实例展开。
8. 基础使用数据、数据来源、可信度和“暂无数据”原因。
9. 按 Skill 写入授权、必要快照、失败回滚和关键操作日志。
10. 永久 UUID、Asset、Skill、Instance、File 等底层数据模型。

### 4.2 P1：完整管理版本

1. Insights 数据总览、活跃度、调用与 Token 趋势。
2. SKILL.md 内置编辑器和其他文本文件编辑/外部打开。
3. 草稿、Diff、文件级快照和完整 Skill 包快照。
4. 外部文件冲突检查和强制覆盖保护。
5. GitHub、Git、ZIP 链接安装、来源绑定和自动检查更新。
6. 完整更新、自定义更新、三方差异和多实例统一更新。
7. 卸载、保留副本、移出宿主目录和本地修改保护。

### 4.3 P2：生命周期与审计完善

1. 完整 Archive、Restore、Delete 流程。
2. Missing 自动转 Archive 策略。
3. Activity 完整筛选、180 天保留和导出。
4. 审计记录与诊断包。
5. 来源信任的精细权限配置。
6. 长期快照管理、空间管理和手动清理。

### 4.4 最低安全底座

任何进入 P0 或 P1 的写操作必须同时具备：

- 按 Skill 或目录授予写权限。
- 写入前确认目标路径与影响范围。
- 编辑、安装、更新前创建必要快照。
- 写入失败时保留草稿或恢复可控文件改动。
- 记录关键操作、失败原因、退出码和回滚结果。
- 写入前重新校验目标文件当前状态，防止覆盖外部修改。

## 6. 核心对象与术语

| 术语 | 定义 |
|---|---|
| Asset | 底层统一资产实体，1.x 仅对外展示 Skill 类型 |
| Skill | 用户认知中的 Skill 资产，拥有永久 UUID |
| Skill Instance | Skill 在某个宿主或路径中的实际安装实例 |
| Skill Package | 一个 Skill 根目录及目录内全部文件 |
| Formal Index | 当前 Library 正式使用的已确认索引 |
| Scan Result | 本次扫描实时发现的新状态 |
| Change Set | 扫描完成后等待用户确认的变化集合 |
| Managed | 已获得写入管理权限的 Skill 或实例 |
| Read-only | 仅可扫描、查看和本地分类，不可改动原始文件 |
| Missing | 扫描时未找到，但历史信息仍保留的状态 |
| Archive | 从主 Library 隐藏，但保留历史、快照和管理数据的状态 |
| Source Binding | 本地 Skill 与 GitHub、Git 或 ZIP 来源的绑定关系 |
| Official Baseline | 来源绑定时记录的远程基准版本或提交 |
| Local Modification | 当前实例相对官方基准存在的本地差异 |
| Attribution Level | 使用记录与 Skill 的归因等级：准确、部分匹配、无法归因、暂无数据 |

## 7. 首次启动与全盘扫描

### 7.1 首次启动流程

1. 展示产品用途、扫描范围、读取内容和隐私说明。
2. 用户明确授权“全盘发现扫描”。
3. 应用在系统允许访问的范围内扫描整台电脑。
4. 扫描过程中实时展示已发现 Skill，但这些结果处于临时发现状态。
5. 扫描完成后生成变化汇总。
6. 用户确认后，首次正式索引建立，Library 进入正常状态。
7. 用户可以取消扫描；已发现结果可保留为未完成扫描记录，但不得自动建立正式索引。

### 7.2 扫描范围

- 默认尽量扫描所有可访问目录，不主动排除隐藏目录、Git 仓库、依赖目录或构建产物。
- 系统保护目录、无权限目录和不可读位置记录失败原因后跳过，不得导致整个扫描中断。
- Settings 可配置排除目录，但默认不预置大范围排除规则。
- 扫描可读取完整 SKILL.md，以及 Skill 根目录下脚本、配置、参考文档和其他可识别文本文件。
- 二进制文件读取元数据、大小、类型和哈希，不将其作为全文索引内容。
- 超大文件、无法识别编码和敏感文件的具体阈值需在技术方案中确定，并在界面显示跳过原因。

### 7.3 Skill 边界识别

1. 含有 SKILL.md 的目录可被识别为 Skill 根目录。
2. Skill 根目录内部再次出现 SKILL.md 时，不拆分为新的 Skill。
3. 嵌套 SKILL.md 在目录树中显示特殊标记。
4. 名称、路径、内容、文件结构和来源均不直接作为永久主键。
5. 新发现目录由匹配规则判断是否对应已有 UUID，无法确定时进入用户确认或 Rebind 流程。

### 7.4 扫描过程状态

| 状态 | 说明 | 可用操作 |
|---|---|---|
| 未开始 | 尚未获得授权或未启动 | 开始扫描、调整排除规则 |
| 扫描中 | 正在读取目录并建立结果 | 暂停、取消、查看实时结果 |
| 已暂停 | 保留当前位置与已发现结果 | 继续、取消 |
| 已取消 | 本轮扫描结束但未完成 | 查看失败/已发现摘要、重新扫描 |
| 已完成待确认 | 已生成变化集合 | 逐项确认、按类型确认、全部确认、忽略 |
| 已应用 | 变化已进入正式索引 | 返回 Library |
| 部分失败 | 扫描完成但部分目录不可读 | 查看失败目录、重新授权、重新扫描 |

### 7.5 后续重新扫描

- 产品不在启动时自动扫描，不持续监听文件变化，也不后台周期扫描。
- 用户点击“重新扫描”时，每次执行全盘扫描。
- 扫描期间保留旧正式索引，Library 继续可用。
- 本次扫描结果逐步更新，并在 Library 显示临时变化标记。
- 扫描结束后，所有变化默认进入待确认状态。
- Settings 可改为“扫描完成后自动应用”，但自动应用也不得覆盖用户分类、标签、收藏、权限、来源绑定和其他本地管理数据。

### 7.6 扫描变化中心

变化类型包括：

- 新增 Skill。
- Skill 内容变化。
- 路径变化或路径失效。
- 文件删除。
- 重复关系变化。
- 多实例关系变化。
- 健康状态变化。
- 可能属于已有 UUID 的候选重绑定。

支持三级确认粒度：

1. 按变化类型批量确认。
2. 按单个 Skill 接受、忽略或延后。
3. 查看文件树、文本 Diff、哈希和二进制变化后确认。

未确认前，Library 保留旧正式索引，同时显示“待加入”“待更新”“路径失效待确认”“重复关系变化”等标记。

### 7.7 扫描验收标准

- 可扫描系统允许访问的全部目录。
- 遇到单个目录失败时继续扫描。
- 用户可暂停、继续和取消。
- 扫描中实时展示发现数量和当前进度。
- 首次扫描未确认前不建立正式索引。
- 后续扫描未确认前不替换旧索引。
- 扫描后可看到新增、修改、失效、删除和分组变化。
- 用户本地分类、标签、收藏、权限和来源绑定不被覆盖。

## 8. Library

### 8.1 默认入口

Library 默认进入“全部 Skill”，先建立完整资产认知。分类、最近使用和收藏作为辅助入口。

### 8.2 三种视图

| 视图 | 主要用途 | 核心能力 |
|---|---|---|
| 表格视图 | 高密度管理 | 排序、筛选、批量选择、字段配置 |
| 卡片视图 | 快速浏览 | 名称、描述、分类、使用与状态概览 |
| 目录树视图 | 理解实际存放结构 | 磁盘路径、宿主目录、层级和实例位置 |

三种视图使用同一数据源，切换时保留搜索、筛选、当前选中项和右侧快速详情，并记住用户上次使用的视图。

### 8.3 推荐字段

表格和卡片应支持以下信息，具体显示密度由视图决定：

- 名称。
- 简短描述。
- 分类和标签。
- 默认展示分类。
- 实例数量。
- 支持宿主。
- 主路径或主实例。
- 最近使用时间。
- 调用次数。
- 使用会话数。
- 总 Token 和可归因比例。
- 数据可信度。
- 版本与更新状态。
- 权限状态。
- 健康状态。
- 本地修改状态。
- Missing、Archive、重复组等生命周期状态。

### 8.4 搜索

搜索范围：

1. Skill 名称、描述、调用方式。
2. 分类、标签、宿主和路径。
3. SKILL.md 全文。
4. Skill 包内其他已索引文本文件。
5. 文件名和目录名。

搜索结果仍指向同一个 Skill UUID。用户可进一步切换到文件级匹配结果，并查看命中文件和上下文摘要。

### 8.5 筛选与排序

应支持：

- 分类、标签、宿主、目录和来源类型。
- Read-only、Managed。
- 正常、Missing、Archive、安装异常。
- 有无调用数据、归因等级。
- 最近使用时间、调用次数、会话数、Token。
- 有无本地修改、可更新、重复、多实例。
- 文件数量、包体积和文档 Token。

常用排序包括名称、最近使用、调用次数、Token、最近修改、最近扫描、版本和文件规模。

### 8.6 分类与标签

1. 系统根据名称、描述、目录名称、内容关键词、路径和文件特征使用固定规则生成初始分类。
2. 应用提供少量预设大类，具体大类清单需在设计阶段确认。
3. 用户可以新建顶级分类、子分类和标签。
4. 用户可以重命名、隐藏或调整系统分类。
5. 同一 Skill 可属于多个分类，并可指定默认展示分类。
6. 同一 Skill 在所有所属分类下显示，同时标注其他分类。
7. 自动分类标记为“系统分类”，用户修改标记为“用户分类”。
8. 用户分类默认只写入 Skill Panel 本地数据库。
9. 用户可主动同步分类到 SKILL.md，但需获得管理权限并显示 Diff。
10. 后续扫描不得覆盖用户分类结果。

### 8.7 右侧快速详情

所有视图均保留右侧快速详情，内容包括：

- 名称、描述、分类、标签、收藏。
- 权限状态和健康状态。
- 最近使用、调用次数、会话数、Token 与可信度。
- 主路径、宿主、版本、实例数量和来源。
- 调用方式、复制入口和在对应宿主中打开。
- 更新、本地修改、Missing 或重复提醒。

快速详情可直接完成：

- 收藏。
- 复制路径。
- 复制调用方式。
- 调整分类与标签。
- 设置单 Skill 权限。
- 进入编辑器。
- 归档。

复杂冲突、版本恢复、永久删除、实例同步和合并进入完整页面处理。

### 8.8 Library 顶部状态入口

- 扫描中进度。
- 待确认扫描变化数量。
- 可更新 Skill 数量。
- Missing 数量。
- 重复组数量。
- 安装或更新异常数量。

### 8.9 Library 验收标准

- 默认显示全部 Skill。
- 三种视图切换后筛选、选中项和快速详情不丢失。
- 分类、标签和收藏修改后立即保存到本地数据库。
- 同一 Skill 在多个分类中显示时仍指向同一 UUID。
- 可展开查看多实例和重复组。
- “暂无数据”和“0 次使用”在视觉与语义上明确区分。
- Pending、Missing、Archive、Local Modified、Update Available 等状态可识别。

## 9. Skill Detail

### 9.1 信息优先级

详情页按照以下顺序组织：

1. 使用与状态概览。
2. 来源、路径、宿主和安装实例。
3. Skill 完整说明和使用方法。
4. 文件状态、草稿、版本和快照。
5. 调用方式和复制入口。

### 9.2 页面结构

#### A. 顶部概要

- Skill 名称、描述、分类、标签、收藏。
- 当前状态、权限、版本和更新标记。
- 主实例和实例数量。
- 快速操作：编辑、复制调用、在对应宿主中打开、打开目录、更新、更多。

#### B. 使用与数据可信度

- 最近使用时间。
- 调用次数。
- 使用会话数。
- 输入、输出、总 Token。
- 会话总 Token、可归因 Token 和可归因比例。
- 归因等级。
- 数据来源、覆盖时间、最后同步时间、样本量和缺失原因。
- 高级入口：查看脱敏原始日志匹配记录。

#### C. 来源与实例

- 当前路径和宿主。
- 安装方式。
- 主实例。
- 其他实例列表。
- 来源链接、作者或组织、基准版本、提交信息。
- 本地修改数量和差异入口。
- 绑定、解除绑定或更换来源。

#### D. Skill 内容

- 渲染后的 SKILL.md。
- 使用方法和调用示例。
- 可复制调用命令或提示词。
- 内容目录。
- 文档 Token、章节规模和内容变化。

#### E. 文件浏览

- 完整目录树。
- 文件名、类型、大小、修改时间、Token 和哈希。
- 文本预览和全文搜索。
- 二进制文件元数据和外部打开。
- 嵌套 SKILL.md 标记。

#### F. 版本与历史

- 文件级快照。
- 完整 Skill 包快照。
- 更新记录。
- 草稿和未应用修改。
- 外部冲突。
- 恢复入口。

#### G. 管理信息

- 权限来源：单 Skill、目录继承或覆盖。
- Missing/Archive 生命周期。
- Activity 摘要。
- 重复关系和多实例关系。

### 9.3 无数据状态

使用数据区域不得隐藏。无可靠数据时显示“暂无数据”，并说明具体原因：

- 宿主未连接或未授权读取日志。
- 宿主不提供逐 Skill 使用记录。
- 日志覆盖时间不足。
- 记录存在但无法准确匹配。
- 数据同步失败或尚未完成。
- 所选时间范围内没有记录。

只有数据源完整、覆盖范围满足要求且确认无调用记录时，显示“0 次”。

## 10. 文件查看与编辑

### 10.1 编辑范围

| 文件类型 | 默认能力 | 可选能力 |
|---|---|---|
| SKILL.md | 内置查看与编辑 | 外部打开 |
| 其他文本文件 | 内置查看 | 用户选择内置编辑或外部编辑器 |
| 二进制文件 | 元数据预览、定位 | 系统默认应用打开 |
| 无法识别/超大文件 | 显示跳过原因 | 外部打开 |

### 10.2 权限前置

- 默认只读。
- 用户首次编辑时请求该 Skill 的管理权限。
- 用户可对目录批量授权，目录内 Skill 继承。
- 单 Skill 权限可覆盖目录权限。
- 只读状态允许本地分类、标签和收藏，但不允许修改原始文件。

### 10.3 编辑流程

1. 打开目标文件并记录当前哈希与修改时间。
2. 用户编辑，内容自动保存为草稿。
3. 应用前重新读取目标文件状态。
4. 未发生外部变化时展示 Diff。
5. 用户确认后写入。
6. 创建文件级快照并记录 Activity。
7. 写入失败时保留草稿，不丢失用户修改。
8. 外部文件已变化时进入冲突处理。

### 10.4 冲突处理

- 保留本地草稿并重新加载外部版本。
- 查看本地、外部和基准版本差异。
- 用户选择放弃本地修改、覆盖外部修改或人工合并。
- 强制覆盖前创建完整 Skill 包快照。
- 强制覆盖操作进入关键 Activity。

### 10.5 快照机制

#### 文件级快照

适用于普通单文件编辑，保存目标文件修改前内容、修改后内容、时间、操作者、哈希和关联 Activity。

#### 完整 Skill 包快照

以下操作必须创建完整包快照：

- 归档。
- 恢复。
- 永久删除。
- 批量修改多个文件。
- 目录移动或重命名。
- 外部冲突强制覆盖。
- 安装与更新。
- 多实例同步。
- 重复 Skill 合并。
- 用户手动创建完整快照。

### 10.6 快照保留

- 同时受最大数量和最大存储空间限制。
- 达到任一上限后按清理规则处理。
- 用户可为单个 Skill 覆盖全局规则。
- 永久删除前的最终快照进入长期保留区，不参与普通自动清理。
- 长期保留快照只能在再次确认后删除。
- Settings 显示总占用、单 Skill 占用、清理规则和手动清理入口。

### 10.7 固定规则优化提示

当前版本仅基于可验证规则提示：

- 超长章节。
- 重复段落或高度重复文本。
- 文档 Token 明显增长。
- 包含大量未使用或长期未变更文件。
- 同一 Skill 版本更新前后的 Token 变化。
- 调用后 Token 成本变化。

系统只展示依据和变化，不直接判断应删除哪些语义内容，也不自动改写文件。

## 11. 使用数据与 Insights

### 11.1 数据来源

优先读取已支持宿主能够可靠提供的本地日志或历史记录。产品不通过文件打开、编辑、收藏等行为推测真实调用次数。

### 11.2 归因等级

| 等级 | 含义 | 统计处理 |
|---|---|---|
| 准确 | 日志中存在明确 Skill 调用证据 | 进入调用与活跃统计 |
| 部分匹配 | 有较强证据，但存在边界或 Token 切分不完整 | 展示并标注可信度 |
| 无法归因 | 有记录但不能确定属于该 Skill | 不计入该 Skill 准确调用 |
| 暂无数据 | 数据源缺失、覆盖不足或同步失败 | 进入未知活跃状态 |

### 11.3 调用指标

- 调用次数：各宿主日志中明确 Skill 调用的累计次数。
- 使用会话数：同一会话内多次调用同一 Skill 去重后计为一个会话。
- 各宿主可以采用不同识别规则，但必须在详情中说明统计口径、会话边界、覆盖时间和归因等级。
- 跨宿主总览同时展示调用次数和使用会话数。

### 11.4 Token 指标

- 会话总 Token：包含该 Skill 调用的整个会话输入、输出和总 Token。
- 可归因 Token：可明确归属于该 Skill 调用阶段的输入、输出和总 Token。
- 可归因比例：可归因 Token ÷ 会话总 Token。
- 无法准确切分时标记部分归因或无法归因，不使用估算值冒充准确值。

### 11.5 活跃度

- 用户可切换最近 7 天、30 天和 90 天。
- 活跃 Skill 只按真实调用次数判断。
- 编辑、打开和收藏作为独立管理行为展示，不进入活跃排名。
- 没有可靠调用数据的 Skill 进入“未知活跃状态”。
- 未知状态不视为 0 次，也不进入活跃或未活跃。

### 11.6 近期使用率

同时展示：

1. 已知数据使用率 = 活跃 Skill 数 ÷ 有可靠调用数据的 Skill 数。
2. 未知状态占比 = 调用数据不可用的 Skill 数 ÷ 全部 Skill 数。

### 11.7 Insights 首页指标优先级

1. 总 Skill 数、活跃 Skill 数、近期使用率。
2. 调用次数、最近使用趋势、活跃排名。
3. Token 总量、平均 Token、Token 趋势。
4. 按宿主、分类和目录的使用分布。
5. 异常、草稿、重复和归档建议数量。
6. 数据完整度、归因准确率和同步状态。

### 11.8 Insights 页面结构

#### 数据总览

- 时间范围切换。
- 核心指标卡。
- 活跃趋势。
- 调用次数与会话数趋势。
- Token 趋势和可归因比例。
- 活跃 Skill 排名。

#### 分布分析

- 按分类分布。
- 按宿主分布。
- 按目录分布。
- 多实例与单实例对比。

#### 数据质量

- 已连接宿主。
- 数据覆盖时间。
- 最后同步时间。
- 准确、部分匹配、无法归因和暂无数据数量。
- 同步失败和日志权限问题。

#### 任务中心

- 重复组。
- 草稿与外部冲突。
- Missing。
- 归档建议。
- 安装或更新异常。

#### 规则建议

只基于固定规则输出冗长、重复、Token 增长、长期未使用等候选，不自动修改。

### 11.9 原始日志与隐私

默认只展示脱敏摘要：时间、宿主、关联 Skill、Token、匹配结果、调用命令摘要和相关文件名。

完整提示词和回答正文默认不保存、不展示。权限控制为：

1. 全局开关，默认关闭。
2. 单 Skill 覆盖。
3. 按宿主补充限制。

关闭保存功能时弹窗提供：

- 仅停止后续保存，保留历史正文。
- 停止保存并删除全部历史正文。
- 进入清理页，按宿主、Skill 或时间范围删除。

删除正文后仍保留脱敏统计、Token、时间、归因等级和匹配证据，正文不可恢复。

## 12. 权限、隐私与安全

### 12.1 权限分层

| 权限类型 | 作用 | 默认状态 |
|---|---|---|
| 扫描读取权限 | 发现目录、读取 Skill 包并建立索引 | 首次启动由用户明确授权 |
| 日志读取权限 | 读取宿主日志和历史记录 | 按宿主授权 |
| Skill 管理权限 | 编辑、移动、归档、恢复、删除 | 默认关闭，按 Skill 授权 |
| 目录管理权限 | 对目录内 Skill 提供批量写权限 | 默认关闭 |
| 完整正文权限 | 保存和查看完整提示词与回答 | 默认关闭 |
| 脚本执行权限 | 执行安装或更新脚本 | 每次操作默认重新确认 |
| 额外路径权限 | 命令访问 Skill 和目标目录之外的路径 | 每次请求时单独授权 |

### 12.2 权限继承

- 目录管理权限可被 Skill 继承。
- Skill 单独设置可覆盖目录设置。
- 权限状态显示来源与生效范围。
- 撤销目录权限后，单独授权的 Skill 保持自身设置。
- 撤销 Skill 权限后，该 Skill 立即恢复只读。

### 12.3 安全提示原则

风险提示必须说明：

- 触发风险的文件或命令。
- 访问路径和权限范围。
- 可能影响的实例。
- 是否存在本地修改。
- 是否已创建快照。
- 哪些变更能够回滚，哪些外部变更无法保证回滚。

### 12.4 本地数据

分类、标签、收藏、权限状态、统计、设置、快照和草稿均为当前设备本地管理数据。产品不提供跨设备恢复。Activity 可导出，但导出不作为迁移入口。

## 13. 重复 Skill 与多实例

### 13.1 重复检测优先级

1. 整个 Skill 包文件结构与哈希相似度。
2. SKILL.md 内容相似度。
3. 来源、版本和作者信息。
4. 名称相同仅作为弱信号。

重复等级：完全重复、高度相似、可能相关、仅名称相同。

### 13.2 重复组展示

- Library 先将候选实例合并为重复组展示，不移动或修改文件。
- 展开后查看路径、版本、文件差异、使用数据和健康状态。
- 用户可解除重复提醒，不改变磁盘文件。

### 13.3 重复组处理结果

1. 保留全部并解除提醒。
2. 保留一个，其余归档或删除。
3. 将多个实例关联为同一个多实例 Skill。
4. 合并文件内容生成新 Skill。

### 13.4 合并文件规则

- 无冲突文件自动合并。
- 同名文本冲突进入人工处理。
- 二进制文件选择保留某一版本或同时保留。
- 当前版本不使用 AI 自动解决文本冲突。
- 合并前创建完整包快照。
- 新 Skill 建立后，用户分别选择原实例保留、归档或删除，默认推荐归档。

### 13.5 多实例分组

- 内容一致时，Library 默认合并为一个 Skill 条目并可展开实例。
- 内容不同或发生分叉时拆分显示，并标记版本差异或内容分叉。
- 用户可手动合并或取消分组。
- 合并展示只影响 UI，底层实例始终独立保存路径、权限、使用数据、健康状态和更新记录。

### 13.6 主实例

- 用户可指定主实例。
- 主实例是默认编辑对象和更新基准。
- 主实例不影响使用数据汇总。

### 13.7 多实例编辑

- 每次应用修改前选择“仅当前实例”或“同步全部已合并实例”。
- 内容已分叉时默认仅修改当前实例。
- 同步前展示差异和影响范围。
- 批量同步前为每个实例创建完整包快照。
- 部分实例写入失败时，成功实例不回滚，整体标记“部分成功”。

### 13.8 多实例数据

顶部汇总全部实例的调用次数、会话数、输入 Token、输出 Token、总 Token 和可归因比例；明细按宿主、实例、路径和版本拆分。跨宿主重复记录尽量去重，无法确认的记录保留并标注口径。

## 14. 安装、来源绑定、更新与卸载

### 14.1 范围

支持 GitHub、Git 仓库和 ZIP 链接安装与更新。当前不建设官方商店，也不自动追溯电脑中已有 Skill 的原始来源。

### 14.2 安装入口

- Library 顶部“安装 Skill”。
- 粘贴 GitHub、Git 或 ZIP 链接。
- 后续可扩展本地文件夹或压缩包导入。

### 14.3 安装位置

- 根据 Skill 支持宿主自动推荐目录。
- 读取 Settings 默认安装目录。
- 用户安装前确认并可临时修改。
- 安装完成后自动进入 Library，记录来源、路径、版本和更新信息。

### 14.4 多宿主安装方式

当 Skill 同时支持多个宿主时，由用户选择：

1. 单份安装，通过软链接提供给其他宿主。
2. 分别复制到多个宿主目录，作为多个实例。
3. 安装一份源文件，由 Skill Panel 维护多个宿主绑定。

安装页必须说明更新同步、路径权限、实例独立性和卸载影响。系统可推荐方案，但必须由用户确认。

### 14.5 安装安全检查

检查并展示：

- 链接可访问性和下载完整性。
- Skill 目录结构和 SKILL.md。
- 新增脚本、可执行文件和依赖声明。
- 符号链接。
- 敏感路径访问。
- 文件类型、大小和哈希。
- 来源作者、组织、更新时间、提交记录和发布版本。

系统展示风险等级和触发依据，但不自动阻止用户继续安装。

### 14.6 脚本与依赖执行

- 默认禁止自动执行。
- 用户可在单次安装或更新中逐项查看命令、工作目录、权限需求和风险后确认。
- 每次授权仅对当前流程有效，除非用户针对可信来源明确配置长期权限。
- 默认在 Skill Panel 受控终端运行。
- 需要输入、登录、授权或交互时切换到系统终端。
- 切换后明确标记追踪边界，并在结束后验证安装结果。

### 14.7 受控终端权限

- 默认只能访问当前 Skill 目录和安装目标目录。
- 尝试访问其他路径时暂停并请求单次授权。
- 额外授权目录、命令、执行结果和失败原因写入 Activity。

### 14.8 安装失败回滚

- 自动恢复 Skill 文件和安装目录内的改动。
- 外部依赖、全局包、系统配置和其他目录改动只记录，不保证自动恢复。
- 结果区分“已恢复内容”和“需手动处理内容”。
- 无法完整恢复时标记“安装异常”，提供重新安装、打开目录和查看日志入口。

### 14.9 现有本地 Skill 绑定来源

产品默认只记录路径，不主动追溯来源。用户主动绑定时：

1. 比较 SKILL.md、目录结构、文件清单和文件哈希。
2. 展示本地与远程差异。
3. 创建完整 Skill 包快照。
4. 用户确认是否为同一 Skill。
5. 用户选择以本地或远程内容建立基准，也可选择合并或覆盖。
6. 保存远程基准版本、提交、本地差异和绑定时间。

### 14.10 解除来源绑定

- 当前文件保留，Skill 恢复为普通本地 Skill。
- 用户选择保留或清除来源历史。
- 保留历史时旧来源与更新记录只读保存。
- 清除历史时删除绑定关系和远程基准，不删除文件、快照和 Activity。
- 之后可重新绑定其他来源。

### 14.11 更新检查

- 链接安装或已绑定来源的 Skill 默认自动检查更新，不自动安装。
- 单 Skill 可覆盖检查开关和频率。
- Skill 条目、快速详情和 Detail 显示当前版本、最新版本、上次检查时间和来源可信度。
- Library 顶部提供“可更新 Skill”集中入口。

### 14.12 来源信任

信任对象以“仓库＋作者/组织”组合为主。仓库所有权转移后信任失效。脚本长期授权还需绑定具体版本或提交哈希。

用户可将来源标记为“信任”或“不信任”，并查看该来源的安装、更新、失败与回滚历史。可信度只影响提示和默认建议，不自动阻止安装。用户可分别配置：

- 自动下载。
- 自动更新。
- 执行安装脚本。
- 访问额外路径。

各项默认独立关闭。脚本和额外路径支持“每次确认、仅本次允许、对该来源长期允许”。撤销信任后立即恢复完整确认流程。

### 14.13 重新确认条件

以下变化触发安全重新确认：

- 安装脚本变化。
- 依赖声明变化。
- 权限需求或访问范围变化。
- 可执行文件变化。
- 符号链接变化。
- 作者、组织归属、签名或提交身份变化。

普通 SKILL.md 和常规文本更新不单独触发安全确认，但仍进入更新 Diff。

### 14.14 更新 Diff

更新前展示整个 Skill 包：

- 新增、修改、删除文件。
- 脚本、依赖、权限、可执行文件和符号链接高亮。
- 文本文件逐文件 Diff。
- 二进制文件大小、哈希和类型变化。

### 14.15 更新模式

#### 完整更新

完整应用官方版本。

#### 自定义更新

用户逐文件选择。系统提示可能导致文件组合与官方版本不一致；更新前创建完整包快照，并记录排除文件、最终哈希和结果。

自定义更新后显示：

`官方基准版本 · 本地修改`

详情中展示官方基准、被排除/修改/新增文件、差异数量、更新检查状态和后续冲突。

### 14.16 三方差异

后续更新基于：

1. 当前本地状态。
2. 当前官方基准版本。
3. 新官方版本。

系统不得直接覆盖用户保留文件。

### 14.17 多实例更新

- 默认所有实例统一更新到最新版本。
- 更新前检查每个实例路径、权限、版本和本地差异。
- 每个实例创建完整包快照。
- 部分失败时标记“部分成功”，列出失败原因和回滚入口。
- 已分叉实例仍进入统一更新流程，但提前提示本地修改可能受影响。

### 14.18 本地修改冲突

用户选择：

1. 跳过冲突实例，其余继续更新。
2. 保留本地修改，更新后进入人工合并。
3. 将本地修改复制为独立分支或副本，再更新原实例。

系统不得默认覆盖本地修改。

### 14.19 卸载

提供三种方式：

1. 保留副本：将当前 Skill 包保存到用户指定位置后卸载。
2. 仅移出宿主目录：停止在宿主中生效，保留 Skill Panel 管理副本、快照和历史。
3. 彻底删除：删除安装文件，默认保留安装记录、Activity 和长期快照。

存在本地修改、未应用草稿或未同步实例时，必须列出差异，并要求用户选择导出副本、保留管理副本或确认放弃修改。

## 15. Activity

### 15.1 定位

Activity 是完整操作审计页面，重点记录会改变数据、文件、权限或状态的操作，以及扫描、同步、导出和诊断。真实 Skill 调用历史不作为 Activity 主内容。

### 15.2 默认记录范围

- 扫描开始、暂停、取消、完成和失败。
- 扫描变化确认。
- 权限授予、继承、覆盖和撤销。
- 编辑、应用、冲突、强制覆盖。
- 文件级和完整包快照。
- 分类同步写入 SKILL.md。
- 归档、恢复、移动、重命名、删除。
- 来源绑定、解除绑定。
- 安装、更新、卸载。
- 脚本命令、退出码、访问路径和回滚。
- 导出和诊断。
- 失败与部分成功。

不默认记录查看详情、搜索、筛选、复制路径和普通复制调用方式。

### 15.3 事件字段

- 时间。
- 事件类型。
- Skill UUID 和实例 ID。
- 目标路径。
- 操作结果。
- 失败原因。
- 快照 ID。
- 权限与影响范围。
- 执行命令和退出码。
- 回滚结果。
- 脱敏诊断信息。

### 15.4 保留与清理

- 默认保留 180 天。
- 用户可在 Settings 调整。
- 到期后自动清理。
- 如需长期留存，用户手动导出。

### 15.5 导出

#### 审计记录

用于用户备份、查看和排查管理历史，输出可读事件列表。

#### 诊断包

用于向开发者提交故障，包含应用版本、宿主适配器状态、失败信息和脱敏路径。不得包含 Skill 正文、完整提示词、回答正文或敏感凭据。

## 16. Missing、Archive 与删除生命周期

### 16.1 生命周期

`Available → Missing → Archive → Permanently Deleted`

### 16.2 Missing

扫描未发现 Skill 时，不立即删除。保留：

- 分类、标签和收藏。
- 权限。
- 使用统计。
- Activity。
- 快照。
- 来源绑定。
- 多实例和重复关系历史。

支持：

- Relink 新路径。
- 等待下次扫描恢复。
- 手动归档。
- 手动删除。

### 16.3 Archive

Missing 超过设定时间后可自动归档。Archive 默认从 Library 主视图隐藏，但保留所有历史数据。用户可在 Archive 页面恢复、重新绑定或彻底删除。

### 16.4 Settings 策略

- Missing 保留时长。
- 是否自动归档。
- 自动归档时间：30/60/90 天或自定义。
- 归档后是否参与统计分析。
- Library 是否显示 Missing 项。

默认具体时长尚未在 96 项决策中确定，发布前需确认。

### 16.5 永久删除

- 删除前创建最终完整包快照。
- 最终快照进入长期保留区。
- 用户再次确认后才能删除长期快照。
- 删除界面必须列出文件、实例、来源绑定、本地修改和不可恢复影响。

## 18. 数据模型

### 18.1 总体原则

底层统一使用 Asset 模型，Skill 是 `asset_type = skill` 的一种类型。1.x UI 不暴露其他 Asset 类型。

每个 Skill 首次扫描或导入时生成永久 UUID。名称、路径、版本、仓库和作者均为可变属性。Library、Insights、Activity、Snapshot、Tag、Category、Permission 和 Usage 全部绑定 UUID。

### 18.2 核心实体

#### Asset

| 字段 | 说明 |
|---|---|
| asset_id | 永久 UUID，主键 |
| asset_type | 1.x 固定为 skill |
| name | 当前名称 |
| description | 当前描述 |
| lifecycle_status | available、missing、archived 等 |
| created_at | 首次进入数据库时间 |
| updated_at | 本地管理数据更新时间 |
| default_category_id | 默认展示分类 |
| favorite | 收藏状态 |
| metadata | 可扩展元数据 |

#### Skill

| 字段 | 说明 |
|---|---|
| asset_id | 关联 Asset |
| skill_schema | SKILL.md 结构版本 |
| invocation | 调用方式或命令 |
| supported_hosts | 支持宿主 |
| document_token_count | SKILL.md Token |
| package_token_count | 全包文本 Token |
| health_status | 健康状态 |

#### SkillInstance

| 字段 | 说明 |
|---|---|
| instance_id | 实例主键 |
| asset_id | 所属 Skill UUID |
| path | 实际路径 |
| host | 宿主 |
| is_primary | 是否主实例 |
| permission_state | read_only、managed |
| content_hash | 包内容哈希 |
| version | 当前版本 |
| baseline_version | 官方基准版本 |
| local_modified | 是否存在本地修改 |
| instance_status | available、missing、install_error 等 |

#### AssetFile

| 字段 | 说明 |
|---|---|
| file_id | 文件主键 |
| instance_id | 所属实例 |
| relative_path | 相对路径 |
| file_type | text、binary、symlink、unknown |
| size | 文件大小 |
| hash | 文件哈希 |
| token_count | 文本 Token |
| modified_at | 文件修改时间 |
| index_status | indexed、skipped、failed |

#### Category / Tag

支持分类树、多对多 Skill 分类关系、默认分类、系统分类和用户分类来源。标签为多对多关系。

#### PermissionGrant

记录授权对象、授权范围、继承来源、覆盖关系、授予时间和撤销时间。

#### ScanSession

记录扫描时间、范围、进度、暂停点、结果、失败目录和结束状态。

#### ScanChangeSet

记录本轮新增、修改、Missing、删除、分组变化及用户确认状态。

#### Snapshot

记录文件级或完整包级别、触发操作、存储位置、哈希、大小、保留策略和长期保留标记。

#### UsageRecord

记录宿主、时间、会话 ID、实例、调用次数、Token、归因等级和脱敏匹配证据。

#### SourceBinding

记录来源类型、链接、作者/组织、仓库、基准版本、提交、绑定时间和信任状态。

#### UpdateRecord

记录旧版本、新版本、更新模式、排除文件、实例结果、冲突、快照和回滚。

#### ActivityEvent

记录操作类型、对象、路径、结果、失败原因、权限、快照和诊断字段。

### 18.3 UUID 与 Rebind

- 路径改变不创建新 UUID。
- 名称改变不创建新 UUID。
- 版本更新不创建新 UUID。
- 来源更换不创建新 UUID。
- 用户确认同一 Skill 时，可将新目录 Rebind 到已有 UUID。
- 用户可将错误关联的实例拆分成新 Skill 实体。
- Rebind 属于高级操作，必须显示将被继承的历史、分类、统计和快照关系。

### 18.4 多实例关系

一个 Asset 可对应多个 SkillInstance。实例分组、重复组和 UI 合并均不得破坏实例独立数据。

## 19. 状态模型

### 19.1 Skill 生命周期状态

| 状态 | 含义 |
|---|---|
| Available | 当前路径存在且已进入正式索引 |
| Pending Add | 本次扫描新发现，等待确认 |
| Pending Update | 内容或路径变化，等待确认 |
| Missing | 扫描未发现，等待恢复或归档 |
| Archived | 从主视图隐藏，历史保留 |
| Deleted | 文件已删除，仍可能保留长期快照与审计 |

### 19.2 实例管理状态

| 状态 | 含义 |
|---|---|
| Read-only | 可浏览，不可写入 |
| Managed | 已授权写入 |
| Local Modified | 相对官方基准存在本地差异 |
| Update Available | 检测到新版本 |
| Conflict | 更新或编辑存在冲突 |
| Partial Success | 多实例写入或更新部分成功 |
| Install Error | 安装或回滚未完全完成 |

### 19.3 数据状态

| 状态 | 含义 |
|---|---|
| Accurate | 可准确归因 |
| Partial Match | 部分匹配 |
| Unattributed | 有记录但无法归因 |
| No Data | 数据源不可用或覆盖不足 |
| Zero Usage | 数据完整且确认无调用 |

## 20. 非功能需求

以下为基于 96 项边界决策推导出的实现要求，具体数值指标需在技术方案和测试计划中补充。

### 20.1 性能

- 全盘扫描不得阻塞 Library 基础浏览。
- 扫描、索引和哈希计算应支持暂停、取消和恢复界面状态。
- Library 在大量 Skill 和文件索引下仍需保持可搜索和可筛选。
- 文件内容索引、Token 计算和重复检测应采用后台任务并显示状态。

### 20.2 可靠性

- 单目录、单文件或单适配器失败不得中断全局流程。
- 所有写操作应具备原子性边界或明确部分成功状态。
- 快照失败时不得继续高风险写操作。
- 应用崩溃后草稿、扫描状态和关键操作结果可恢复或明确标记未知。

### 20.3 数据一致性

- 正式索引与本次扫描结果分离。
- 用户本地管理数据不得被扫描覆盖。
- UUID 不随路径、名称、版本和来源改变。
- 多实例汇总不得丢失实例级明细。

### 20.4 隐私

- 默认不保存完整提示词和回答正文。
- 诊断包必须脱敏。
- 用户可查看当前扫描、日志和正文权限范围。
- 删除完整正文后不可恢复。

### 20.5 可解释性

- 分类结果显示来源。
- 重复判断显示证据和等级。
- 使用统计显示口径、覆盖范围和归因等级。
- 风险提示显示触发文件、命令和权限。
- 自动清理显示规则和影响范围。

## 21. 关键验收清单

### 21.1 发现与 Library

- [ ] 首次启动可授权全盘扫描。
- [ ] 扫描可暂停、取消并展示失败目录。
- [ ] 实时结果与正式索引区分。
- [ ] 扫描变化默认待确认。
- [ ] 三种 Library 视图共享筛选和选中状态。
- [ ] 可查看 Skill 包目录和全文搜索结果。
- [ ] 嵌套 SKILL.md 不被错误拆成独立 Skill。

### 21.2 分类与重复

- [ ] 系统规则可生成初始分类。
- [ ] 用户可新建顶级分类、子分类和标签。
- [ ] 同一 Skill 可进入多个分类。
- [ ] 用户分类不被重新扫描覆盖。
- [ ] 重复判断不只依赖名称。
- [ ] 重复组处理不自动修改磁盘文件。

### 21.3 数据分析

- [ ] “暂无数据”和“0 次”明确区分。
- [ ] 可展示调用次数和使用会话数。
- [ ] 可展示会话总 Token、可归因 Token 和比例。
- [ ] 未知状态不进入活跃率分母。
- [ ] 统计页面显示数据来源与可信度。

### 21.4 编辑与安全

- [ ] 默认只读。

- [ ] 支持 GitHub、Git、ZIP 链接。

- [ ] 受控终端限制默认访问范围。

## 22. 风险与依赖

| 风险/依赖 | 影响 | 产品处理 |
|---|---|---|
| 全盘扫描权限受操作系统限制 | 发现结果不完整 | 显示失败目录、原因和重新授权入口 |
| 扫描范围过大 | 时间长、资源占用高 | 进度、暂停、取消、异步索引和排除规则 |
| 宿主日志格式变化 | 使用数据失效 | 适配器状态、覆盖时间和同步失败提示 |
| 无法逐 Skill 归因 | Insights 不完整 | 未知状态、可信度和原因说明 |
| 多实例和本地修改复杂 | 更新冲突高 | 主实例、Diff、三方比较、快照和部分成功 |
| 安装脚本造成外部变更 | 无法完整回滚 | 默认禁止、权限限制、风险提示和遗留变更清单 |
| 快照占用大量空间 | 本地存储压力 | 数量与空间双限制、单 Skill 覆盖和清理中心 |
| 永久 UUID 错误关联 | 历史数据混乱 | 候选确认、Rebind 和拆分实体 |
| 分类规则不准确 | Library 组织混乱 | 标注系统分类、允许用户覆盖且不被扫描覆盖 |

## 26. 结论

Skill Panel 1.x 的首要任务，是让用户快速看清电脑里有哪些 Skill、每个 Skill 包含什么、如何使用、是否仍在使用，以及它们之间是否重复、分叉、失效或可更新。

产品以 Library 为绝对核心，以 Insights、编辑、安装更新和生命周期管理作为辅助能力；以默认只读、按 Skill 授权、快照、Diff、回滚和可信度说明作为安全基础；以永久 UUID、Skill Instance 和 Asset 模型保证长期演进。

PRD 5.0 的产品路线为：

`Skill Manager → AI Asset Manager → AI Workspace`

1.x 的界面保持聚焦，底层从第一天起具备向完整 AI 工作资产平台扩展的能力。

# 安全基线

## 默认策略

- 默认只读。
- 权限按能力、目录和实例分层。
- 写入、覆盖、移动、删除、批量操作和脚本执行需要显式确认。
- 重要写入前必须完成快照和目标状态复核。
- 后台任务禁止静默修改用户文件。

## 信任边界

以下输入都按不可信处理：

- Skill 名称、正文、frontmatter、文件名和目录名。
- 远程来源、压缩包、Git 仓库和 manifest。
- 宿主日志、命令输出和错误文本。
- 符号链接、相对路径、编码和 MIME 声明。

UI 动态文本使用 React 默认转义。Rust 在打开文件前完成路径规范化、允许根目录校验和符号
链接策略判定。

## 写入门禁

每次写入依次检查：

1. 用户已授权的能力与范围。
2. 目标位于允许根目录内。
3. 规范化路径未逃逸。
4. 文件类型、符号链接和目标状态符合预期。
5. 当前哈希与编辑基线一致。
6. 快照已成功创建并校验。
7. 用户已看到路径、文件和影响范围。
8. 写入采用临时文件与原子替换，或返回明确部分成功状态。

## 日志与诊断

- 路径显示为根目录别名加相对路径。
- 用户名、邮箱、密钥、Token、正文和查询内容默认移除。
- 错误面向 UI 提供稳定代码和安全摘要。
- 详细诊断只保存必要字段，并遵守保留期限。
- 截图和测试 fixture 禁止包含真实用户路径或内容。

## 依赖与 CI

- npm 使用 lockfile 和 `npm ci`。
- Rust 使用 `Cargo.lock`。
- CI 不读取生产 secrets，不执行真实用户目录扫描。
- 依赖新增需核对官方兼容性、许可证与维护状态。
- 脚本命令保持仓库内可审阅，禁止下载后直接执行未知脚本。

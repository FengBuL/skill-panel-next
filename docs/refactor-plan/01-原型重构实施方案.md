# Skill Panel 1.x 原型重构实施方案

## 1. 改造目标

将现有原型从“已授权目录中的单文件 Skill 管理”升级为完整的 Skill Manager 1.x 原型，形成以下闭环：

`首次授权 → 全盘发现扫描 → 扫描变化确认 → 正式 Library → 查看 Skill 包与实例 → 分类和搜索 → 编辑与快照 → 安装与更新 → 冲突和回滚 → Missing / Archive / 卸载管理`

本次重点是产品逻辑、信息架构、页面流程和状态一致性。视觉风格继续使用克制的 macOS 桌面生产力工具方向，视觉调整不得替代产品结构重构。

## 2. 当前原型的主要结构问题

1. Skill 与路径一一绑定，无法表达同一 Skill 的多个实例。
2. 缺少 Formal Index、Scan Result、Change Set 三层扫描模型。
3. 缺少首次扫描、扫描进度、暂停取消、失败目录和变化确认。
4. Library 缺少卡片视图、目录树视图、Missing、可更新和扫描变化入口。
5. Detail 只围绕 SKILL.md，缺少完整 Skill Package 文件树。
6. 默认只读未落实，读取权限和写入权限没有分开。
7. 安装、更新、来源绑定、三方差异、卸载和回滚流程缺失。
8. Missing 生命周期缺失，Ignored 被错误用作 Skill 主生命周期。
9. Insights 被设计成待处理任务页，缺少真正的数据看板。
10. Activity 混入大量调用记录，审计事件与待处理任务没有分开。
11. `shared.js` 的状态模型仍以单 Skill、单路径、单文件为中心。
12. 页面重复声明 CSS，`shared.css` 无法成为统一样式源。

## 3. 重构原则

### 3.1 先状态，后页面

先重构 `shared.js` 的统一状态源和对象模型，再重写页面。禁止在旧状态模型上继续叠加安装、更新和多实例功能。

### 3.2 先主链路，后边缘能力

优先完成扫描、Library、Detail、权限、安装更新和 Missing。Insights、Activity、Settings 在主链路稳定后重构。

### 3.3 原型模拟必须确定

允许模拟本地扫描、GitHub、Git 和 ZIP 结果，但同一输入必须得到同一结果。不得使用 `Math.random()` 决定校验、健康状态、冲突或安装结果。

### 3.4 默认只读

扫描和浏览只获得读取权限。编辑、更新、归档移动、卸载和覆盖前，必须展示目标实例、目标路径、影响范围和写入权限。

### 3.5 高风险操作可回滚

编辑、更新、覆盖、合并、移动、归档和卸载前，在原型状态中创建对应快照；失败结果必须保留草稿或提供回滚状态。

### 3.6 数据可信

必须区分：

- `0 次使用`：有可靠数据且确认为零。
- `暂无数据`：宿主不支持或未连接数据源。
- `部分匹配`：只能部分归因。
- `无法归因`：存在使用记录但无法关联具体 Skill。

## 4. 实施阶段

### 阶段 A：工程与状态基线

交付：

- 统一 `shared.css`，页面只保留页面专属样式。
- `shared.js` 状态版本升级到 v3。
- 新增 Skill、Instance、File、SourceBinding、PermissionGrant、ScanSession、ChangeSet 等对象。
- 修复草稿保存、对象规范化、任务关联、返回上下文和重复组参数问题。
- 建立确定性模拟数据和调试入口。

阶段验收：页面可以使用新状态读取现有 Skill；一个 Skill 可包含多个实例；每个实例可包含多个文件。

### 阶段 B：扫描与正式索引

交付：

- 首次启动授权页。
- 扫描进度页面或全局扫描层。
- 暂停、继续、取消、部分失败。
- 扫描变化中心。
- Formal Index 与临时 Scan Result 分离。
- 逐项、按类型和全部确认变化。

阶段验收：未确认的扫描结果不会直接替换正式 Library；旧 Library 在扫描时仍可浏览。

### 阶段 C：Library 重构

交付：

- 二级入口：全部、分类、收藏、最近使用、可更新、Missing、Archive、扫描变化。
- 表格、卡片、目录树三种视图。
- 统一搜索、筛选、排序和选中状态。
- 右侧快速详情。
- 多实例聚合与展开。
- 状态入口和批量操作。

阶段验收：三种视图切换不丢失搜索、筛选、选中 Skill 和右侧详情。

### 阶段 D：Detail、文件和权限

交付：

- 完整 Skill Package 文件树。
- 文件查看器。
- 使用与数据可信度。
- 来源和实例面板。
- 权限面板。
- 快照、Activity、更新和本地修改状态。
- Missing 的 Relink 流程。

阶段验收：用户可以明确区分 Skill 实体、实例和文件；可对单个实例申请写权限。

### 阶段 E：Editor、冲突和快照

交付：

- 多文件 Editor。
- SKILL.md 内置编辑，其他文本文件内置或外部打开。
- 草稿、文件级快照、完整包快照。
- 保存前重新校验磁盘状态。
- 双向 Diff 和三方 Diff。
- 强制覆盖保护与失败回滚。

阶段验收：无写权限时不能应用更改；外部修改时不能静默覆盖。

### 阶段 F：安装、更新和卸载

交付：

- GitHub、Git、ZIP、本地导入安装向导。
- 来源识别、文件清单、风险检查和目标宿主选择。
- 来源绑定和官方基线。
- 更新检查、完整更新、自定义更新和三方差异。
- 多实例统一更新与部分失败结果。
- 卸载、保留副本、移出宿主目录。

阶段验收：安装更新不自动执行脚本；更新失败可以回滚；本地修改不会被静默覆盖。

### 阶段 G：Insights、Activity、Settings

交付：

- Insights：Dashboard、Pending、Suggestions。
- Activity：只记录管理审计，支持筛选和详情。
- Settings：扫描、Library、权限、数据、快照、安装更新、生命周期、诊断。
- 案例中心仅在开发模式可见。

## 5. 不允许的改造方式

- 只调整颜色、阴影、圆角、留白和卡片尺寸。
- 保留旧单路径 Skill 模型，额外添加 `instances: []` 临时字段敷衍多实例。
- 扫描完成后直接修改 Library，不经过 Change Set。
- 将 Missing 继续当成普通错误标签。
- 把安装设计成单个 URL 输入框加“安装成功”Toast。
- 将更新设计成直接覆盖本地文件。
- 在页面中继续复制整套 Token 和公共组件 CSS。
- 使用随机数模拟校验结果。
- 用名称或路径作为永久实体 ID。

## 6. 最终交付物

1. 可直接打开运行的 HTML/CSS/JS 原型。
2. 全部核心页面和弹层可点击串联。
3. 统一状态源和确定性演示数据。
4. 新旧页面迁移说明。
5. 核心流程测试说明。
6. 未完成能力清单，明确哪些仍为模拟。

# Skill Panel 1.x 原型数据模型与状态机

## 1. 状态源要求

`shared.js` 升级为状态版本 v3。所有页面必须读取同一状态源，禁止页面私自维护业务副本。

原型仍可使用 `localStorage`，但对象关系必须接近正式产品结构。

## 2. 核心对象

### 2.1 Asset / Skill

```js
{
  id: 'uuid',
  assetType: 'skill',
  name: 'pr-review',
  displayName: 'PR Review',
  description: '',
  categoryIds: [],
  tags: [],
  isFavorite: false,
  lifecycleStatus: 'active',
  primaryInstanceId: 'uuid',
  createdAt: '',
  updatedAt: ''
}
```

规则：

- `id` 为永久 UUID。
- 名称、路径、版本和来源均可变化。
- 一个 Skill 可拥有多个 Instance。
- 分类和标签属于 Skill，不应因实例变化丢失。

### 2.9 Draft / Snapshot

Draft 必须绑定 `instanceId + fileId`，不能只绑定 Skill。

Snapshot 支持：

- `file`：单文件快照。
- `package`：完整 Skill 包快照。
- `batch`：批量操作前快照集合。

### 2.10 UsageEvent / Attribution

```js
{
  id: 'uuid',
  skillId: 'uuid|null',
  instanceId: 'uuid|null',
  sessionId: '',
  callCount: 1,

  outputTokens: null,
  totalTokens: null,
  attributionLevel: 'accurate|partial|unattributed|no-data',
```

### 2.11 AuditEvent 与 PendingTask

AuditEvent 是不可变事实；PendingTask 是可解决任务。不得通过修改 AuditEvent 表示“已处理”。

## 3. 状态机

### 3.1 Skill 生命周期

```text
discovered
→ pending-review
→ active
→ missing
→ archived
→ deleted
```

补充：

- `missing → active`：扫描恢复或 Relink。
- `missing → archived`：用户手动归档或达到策略期限。
- `archived → active`：恢复。
- `deleted`：终态，仅保留审计所需最小记录。

`ignored` 不作为 Skill 主生命周期，只用于 ChangeItem、Suggestion、DuplicateGroup 或扫描排除规则。

### 3.2 扫描状态机

```text
idle
→ scanning
↔ paused
→ cancelled
→ completed-pending-confirmation
→ applying
→ applied
```

任何阶段可进入 `partial-failure`，但单目录失败不得中断全部扫描。

### 3.3 编辑状态机

```text
read-only
→ permission-requested
→ editable
→ draft-modified
→ validating
→ diff-review
→ applying
→ applied
```

异常分支：

```text
validating → yaml-error
applying → external-conflict
applying → failed-draft-preserved
external-conflict → merge / reload / save-as / force-overwrite
```

### 3.4 安装状态机

```text
source-input
→ resolving
→ validated
→ target-selection
→ conflict-check
→ confirmation
→ installing
→ verifying
→ completed / partial / failed
```

### 3.5 更新状态机

```text
checking
→ up-to-date / update-available
→ diff-review
→ conflict-check
→ snapshot-created
→ updating
→ verifying
→ completed / partial / failed
→ rollback
```

## 4. 原型数据一致性规则

1. 一个有效实例路径只能对应一个 Instance。
2. 同一 Skill 的多个 Instance 默认聚合显示。
3. 分类、标签、收藏不随扫描覆盖。
4. 扫描未确认前不改变 Formal Index。
5. `getSkill()` 等读取函数不得丢失未声明字段。
6. 读取函数可返回副本，但写入函数必须修改原始 state 对象。
7. 不重复存储可推导关系，例如 PendingTask IDs 可由 `skillId` 查询得到。
8. 所有页面返回时恢复来源页、搜索、筛选、视图、分页、选中项和滚动位置。
9. 所有高风险操作在状态中记录快照和 AuditEvent。
10. 本地文件内容作为不可信输入，动态文本使用 `textContent` 或统一转义。
